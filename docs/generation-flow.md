# 生成フロー図

この図は、予測操作の中で「文字の予測」と「画像生成」がどうつながっているかを示します。

```mermaid
flowchart TD
    A["1. カメラ画像を取得\nブラウザ上で元画像を確保"] --> B["2. 予測用プロンプトを組み立て\n対象・シーン・制約を付与"]
    B --> C["3. Gemini Flash に送る\n入力: 元画像 + 文章プロンプト"]
    C --> D["4. 予測シナリオを生成\n- scenario_description\n- label\n- prediction_prompt"]

    D --> E["5. 1シナリオごとに画像生成へ進む"]
    E --> F["6. 画像生成モデルに送る\n入力: 元画像 + prediction_prompt"]
    F --> G["7. 生成画像を返す\n1シナリオ = 1枚の予測画像"]

    D --> H["文字情報の束\n説明文・ラベル・プロンプト"]
    G --> I["画像情報の束\n生成画像"]

    H --> J["8. 文字と画像をペアにする\n説明文 + 画像 + ラベル"]
    I --> J
    J --> K["9. ブラウザ表示 / 保存\nTouchDesigner へ通知"]
```

## ここでのポイント

- まず「何が起きそうか」を Gemini Flash で文章として予測します。
- そのあと、各予測に対応する「見た目の画像」を画像生成モデルで作ります。
- つまり、1回の予測処理では「文字の予測」と「画像の生成」が分けて走り、最後にペアでまとめて扱います。

## 具体的なイメージ

1. 元画像を入力する
2. Gemini Flash が複数のシナリオを返す
3. 各シナリオに対して画像生成モデルが画像を生成する
4. その結果を「ラベル + 説明文 + 画像」のセットとして表示・保存する
