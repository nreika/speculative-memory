# Turbo通常運用への切り替え（2026-10-18）

- 通常のローカル画像生成は `.env.local` の `LOCAL_IMAGE_ENGINE=qwen21-turbo` でTurboを選択する。入力側で `imageEngine` を指定する必要はない。単画像API・会場・スマホ・シナリオ制御も同じ既定を使う。
- 人数や入力モードによる2511への自動振り分けはない。旧2511用ComfyUIサービスは15:56過ぎにアイドル状態を確認して停止した。重みや過去成果は削除していない。
- Turboは8 steps / CFG 1、参照cropの高さ768を維持。384への縮小は速度候補の評価段階であり、今回の設定には含めない。
- 10月19日の変更後、通常Turboは生成画像を元の画角へ復元し、元写真の背景を貼り戻さず、既存の人物検査・保存へ通す。下の切り替え確認にあるCPU合成は10月18日当時の記録である。無人・3人以上など全画面経路の実写真品質は切り替え時点では未検証。モックによる経路確認と生成品質を混同しない。
- 本番用adapterの実行区分はproductionで、呼び出し元の撮影testフラグ、履歴、通知を偽装しない。保存済み素材の試験は引き続き `test:true, recordHistory:false` を使う。
- `/api/health` の `comfyui`、`comfyQueue`、`comfyuiUrl` と `/api/generation-status` は選択中のTurboサービスを確認する。旧サービス停止による誤った切断表示を避ける。

## 切り替え確認

- Node再起動：15:53:55→15:54:01（スクリプト実測5秒）。接続表示修正の反映：15:56:24→15:56:28（4秒）。
- モデル未指定の通常経路を保存済みの杯の素材で試験。別seed 7919 / 7927 / 7933、画像3枚。最終PNG3枚まで68.745秒、HTTP応答68.755秒。非同期QAの終了時間は含めない。
- 3枚とも `localImageEngine=qwen21-turbo`、adapter実行区分production、CPU合成成功、各1試行。元人数の検査は3枚とも合格。ただし、全項目の生成品質が合格したという意味ではない。
- 本体で関連22テストと型チェックを確認。接続表示の追加修正後、関連12テストと型チェックを再確認。
- 手の増殖、人物・杯の複製、動作未達は別seedで確認済みの残欠陥。Turboへの切り替えを解消済みの宣言にしない。既存固定ガイドラインを維持し、比較・改善を継続する。

## 運用上の注意

- ライブカメラ、停止中のTDタイマーはこの切り替えで再開していない。
- Turboサービスの起動環境は既存の専用環境を使う。PC再起動後の自動起動は今回の切り替えで検証していない。
- ロールバックが必要な場合の設定は `LOCAL_IMAGE_ENGINE=qwen2511`。旧サービスの再起動も必要であり、品質不合格時に自動で戻す処理は設けない。

## 2026-10-19 背景貼り戻しの停止

- 元写真のマスク外画素を戻す合成が、生成原画で消えた手・袖の断片を復活させた。ユーザーの指示により `generateTurboProduction` は全条件で `full-frame` の画角復元結果を返し、背景の貼り戻しを行わない。
- 画角の復元、通常の3枚生成での人物数・重複検査、シナリオで指定した画像素材の合成は維持する。test専用の保護合成adapterは比較用に残す。追加の生成・認識呼び出しや照明補正は加えない。
- 保存済み問題画像のCPU復元結果は1280×720で、保存された復元原画と全RGB画素が一致した。これは貼り戻しによる断片復活の回帰確認であり、原画自体の手指・背景の品質保証ではない。
- 反映後の自然な連続生成で3枚の検査・保存・公開を確認した。通常traceは `compositionMode:full-frame`、`sourceBackgroundComposite:false`、`protectedBackground:false`、`qualityPass:null` を記録する。
